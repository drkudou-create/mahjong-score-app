## B：保存・読み込みの例外処理を追加しました

- 読み込みに失敗した場合：壊れた文字列を別のキーへ退避し、既定値で起動しますが、そのままでは保存しません。空の初期データで上書きしません。
- 保存に失敗した場合：画面に知らせ、保存しようとした内容を別のキーへ退避を試みます。履歴や設定を自動で削除・切り捨てしません。
- 保存が成功したかどうかを返すようにしました。ほかの処理の呼び出し方は変えていません。

## C：バックアップ復元の確認と退避を追加しました

- 読み込む前に、バックアップ側と現在側の要約（履歴件数・日付・名簿数・単価・ウマ）を表示します。
- 要約を表示して確認ダイアログを出し、承認された場合だけ、現在の保存内容を別のキーへ退避し、退避できたことを確認してから置き換えます。退避に失敗した場合は、置き換えを行いません。キャンセルした場合は、退避キーを作成しません。
- 確認で「やめる」を選んだ場合は、何も書き込みません。
- 形式の確認は、履歴と名簿が配列であることに加え、各対局に日付・名前・スコアがあることを確認します。未知の項目は削除しません。

- 復元の手順（v2）：要約の確認 → 承認後に退避 → 退避の確認 → 現在の状態の退避（メモリ）→ 置き換え → 保存。保存に失敗した場合は、メモリの状態と保存禁止フラグを復元前の状態に戻します。キャンセルした場合は、退避キーを作成しません。
